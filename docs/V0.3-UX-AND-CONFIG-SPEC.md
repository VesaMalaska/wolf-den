# Wolf Den v0.3 — Cockpit UX, themes and editable configuration

**Status:** Product direction approved; specification for implementation slices, not implemented behavior.
**Authority:** [Roadmap](ROADMAP.md), focused GitHub issue for each slice, and `AGENTS.md`.

## Outcome and product principles

Wolf Den is a local-first, keyboard-driven **developer cockpit**. At a glance, it must answer:

1. **Across my projects, what deserves my attention?**
2. **For this selected project, what should I do next?**

Show factual state, not invented urgency. A dirty working tree, open PR count or temporarily unavailable GitHub data is **not** a generic health failure. Maintain read-only Git/GitHub access and explicit project registration. Do not add AI planning, a task board, project auto-discovery, a database or a daemon.

The visual identity should be distinctively Wolf Den (quiet night/forest/moonlight character, occasional friendly empty states), but readable and professional rather than decorative or gimmicky. Standard concepts retain standard labels.

## Information architecture

### Dashboard / cockpit (default)

- Left: **project radar**. Visible project count and a small factual aggregate (e.g. total projects, dirty Git trees, unavailable Git states) derived only from current loaded states. Per-project identity, a stable selection/focus marker, branch, readable clean/dirty/unavailable state, and optional *available* GitHub count signal where space allows. No invented health score or inferred priority.
- Right: **selected-project workbench**. Strong project identity and lifecycle, restrained path metadata, visually highlighted editable **Next action**, separated **Local Git** and **GitHub** summary zones, and navigable **Pull requests**.
- PR list: compact individual rows with number, readable truncated title, and truthful draft/open state. Show detailed review/check metadata for the selected PR rather than repeating absent/unavailable statuses on every row. Unknown/no checks is not a failure. The selected PR must remain visible while scrolling.
- Footer: stable context-sensitive hints for the current view, prioritizing essential keys; comprehensive shortcuts stay in `?` help. Never obscure actionable content when width/height shrink.
- Preserve wide side-by-side and compact stacked layouts; graceful degradation at approximately 120×32, 100×25, 80×24, 56×22 and 42×18. Clear clipping, no orphan single-character wraps, no off-screen focused item. Consider middle truncation of long Git branches where it preserves more useful context.

### Settings (dedicated view, not another dashboard pane)

Accessible from the dashboard via proposed `s` shortcut (check collisions before implementation), returning with `Esc` to the same selected project/PR and scroll context. Sections:

- **Appearance:** select theme preset (initially *Wolfy Dark* only), edit supported color overrides, preview, save, cancel/restore and reset to preset.
- **Projects:** add, edit essential registration fields, and **Remove from Den**. Removal changes only Wolf Den configuration; never touches a directory, Git repository or GitHub data.
- **General:** existing terminal preference with validation; avoid exposing settings the app cannot actually control.

Clear keyboard focus, understandable validation/help, error recovery, and accessible controls without mouse dependency. The terminal emulator owns font family/size: **no font picker in v0.3**. A future app-level density/symbol preference is permissible only with a concrete use case.

### Direct next-action editing

Proposed `n` shortcut in the dashboard edits the selected project's manually authored `nextAction` without visiting Settings. Save/cancel, empty/cleared action, and clear failure feedback must be supported; never infer or synchronize this field from PRs or Git history.

## Semantic theme foundation

Use central semantic tokens, not literal hex values scattered across UI components:

- Surfaces: `background`, `panel`, `panelAlt`, `selectionBackground`, `focusBorder`
- Text: `textPrimary`, `textSecondary`, `textMuted`, `textOnSelection`
- Identity: `accent`, `accentSubtle`, `heading`, `divider`
- Status: `success`, `attention`, `error`, `unavailable`, `info`

Proposed **Wolfy Dark** palette (starting visual direction, tune during human review):

| Role | Color |
| --- | --- |
| Main background | `#20242E` |
| Surface | `#2C3140` |
| Moonlight / selection focus | `#82CBE1` |
| Plum / next-action accent | `#AE8ACB` |
| Pine / clean-success | `#82BFA0` |
| Amber / attention | `#E6B46A` |

These are palette anchors, not a mandate to use accent as body text everywhere. Provide readable neutral text and practical high contrast. Different terminal backgrounds/transparency (Kitty and COSMIC Terminal) must not destroy meaning; provide semantic text labels/markers as well as colors.

Provide a small typed theme registry and one bundled preset. Future presets must be addable without changing all components. Avoid premature theme plugins, user-authored executable themes, complex theme import/export and new dependencies. Add tests covering token completeness, value validation and UI semantic use.

### Configuration contract

The current registry is `~/.config/wolf-den/projects.json`, with `version: 1` and optional `settings.terminal`. Extend additively (backwards compatible), with an optional conceptual shape:

```json
{
  "version": 1,
  "settings": {
    "terminal": "kitty",
    "theme": "wolfy-dark",
    "themeOverrides": {
      "accent": "#AE8ACB",
      "selectionBackground": "#35516A"
    }
  },
  "projects": []
}
```

This is a proposal, not shipped behavior. Defaults must render old version-1 registries unchanged. Unknown presets, invalid hex values or invalid override tokens produce actionable validation errors; do not silently change unsupported values. Persist only the user's chosen overrides, never dump a hardcoded palette into every registry.

Theme preview is ephemeral. **Cancel restores previous appearance and does not write.** **Save** persists a validated selection. **Reset** returns to the built-in preset (saving only when the user confirms). No restarts required if safely feasible.

## Configuration persistence: explicit safety boundary

Git and GitHub remain **read-only**; only Wolf Den's own configuration may be edited. Before enabling any UI writes, introduce a well-tested dedicated configuration persistence service, separate from OpenTUI:

- Validate with the same schema before writes and after re-reads; keep `version: 1` compatible unless a justified migration is explicitly designed.
- Write a temporary file in the same configuration directory with restrictive permissions, flush as appropriate, and atomically rename into place. No partial/truncated config when a write fails.
- Detect external edits between load and save (snapshot/version or file fingerprint); never silently overwrite another editor's changes. Offer an actionable reload/retry message.
- Preserve legitimate existing fields, project order and configured paths (including user `~/` paths); never serialize the normalized runtime-only absolute paths accidentally.
- Handle missing file/dir, permission failures, malformed JSON, concurrent in-app actions, and interrupted writes. No sensitive values in logs. Avoid following unexpected symlinks where unsafe.
- Keep local-only config outside the repository; no API token storage. Document recovery/backup advice. Never modify or delete project directories, nor execute arbitrary project commands.

## Project management boundaries

- **Add:** required non-empty name and local absolute or `~/` path; generate a stable valid unique ID from name with collision handling; optional GitHub `owner/name`, lifecycle and next action. Respect existing validation. Non-Git or unavailable paths may be registered with an honest warning, consistent with the current dashboard.
- **Edit:** essential name/path/repository/lifecycle fields, not an elaborate project manager. Preserve project identity and selection.
- **Remove from Den:** require a clear confirmation saying *only the registry entry is removed*. Safe cancel. Never delete files, run Git commands or change GitHub repositories. Offer sensible empty-state guidance after the last project is removed.
- **Refresh UI:** immediately reflect saved config in navigator/states; clamp selection and clear stale selected PR when the selected project disappears. Failures must not silently lose existing project data.
- **Next action:** easily editable from cockpit; empty/cleared action supported; no task synchronization.

## UX and accessibility acceptance

- Strong information hierarchy: eye sees active project, next action and status before long PR prose.
- Compact PRs avoid repeating `Review unavailable / Checks no checks` on each row; selected PR details retain factual information.
- Contrast, status text/markers, keyboard focus, and screen reader-friendly textual fallbacks where practical in a TUI.
- Small terminal layouts remain navigable, with help and exit always available.
- Different terminal rendering verified in real Kitty; COSMIC Terminal comparison desirable but not a substitute for Kitty acceptance.
- No broken key handling when editing: typeable letters (`s`, `n`, etc.) in forms must not trigger dashboard shortcuts.
- Helpful empty states may have restrained Wolf Den personality. Actual error messages stay explicit and actionable.

## Planned implementation order and dependencies

1. **Theme tokens and Wolfy Dark preset** — typed palette and additive read-only config loading.
2. **Cockpit hierarchy and project radar** — project summaries, next-action emphasis, Git/GitHub zones.
3. **Compact PR list and contextual footer** — PR state and selection, details-on-selection, help hints.
4. **Safe config persistence service** — atomic writes, external edit detection, schema preservation; required by editing features.
5. **Settings experience** — appearance live preview/save/reset and terminal preferences.
6. **Projects manager** — add/edit/remove without touching filesystem repositories.
7. **Direct next-action editor** — fast edit from cockpit with correct save/cancel.
8. **Real Kitty QA + v0.3 release gate** — automated tests, manual matrix and accessibility, documentation, privacy-safe screenshot. No tag/release without explicit human approval.

Do not begin a dependent slice before its prerequisites have been reviewed and merged. Each slice lives on its own branch/PR and is approved by the owner. Tests: `pnpm typecheck`, `pnpm test`, `pnpm build`, `git diff --check`. Record real GUI verification limits truthfully.

## Non-goals

No font-family switching, automatic theme marketplace, arbitrary user CSS/JS, automatic repository discovery, repository deletion, Git writes, issue/PR editing, daemon, AI orchestration, database, sync or task management. Avoid invented urgency or health ratings.
